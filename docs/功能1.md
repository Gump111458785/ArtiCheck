# 任务：为现有论文审查平台新增「学术贡献知识图谱」模块

**项目名称：Review-Aware Scientific Contribution Graph（审查感知型学术贡献图谱）**

**版本：V2.0 — 最终实施需求**

## 0. 你的角色与核心约束

你是一名负责现有论文审查平台功能扩展的全栈工程师，同时需要具备学术知识图谱、论文贡献抽取、学术证据核验与交互式数据可视化的产品理解能力。

本次任务是在现有论文审查网页中新增独立的知识图谱功能，而不是重构、替换或重新实现原有论文审查系统。

最终需要实现一个可自由拖拽、缩放、展开、比较、探索的学术知识网络。

该网络不仅展示论文之间的引用关系，还能够细化到具体贡献、子论点、实验、指标、审查发现及其跨论文关联。

---

# 1. 产品目标

## 1.1 核心定位

构建一个以 **Paper → Contribution → Claim → Evidence / ReviewFinding** 为主要内部层次、以贡献间关系为跨论文连接的学术知识图谱。

系统同时服务两个主要场景：
- **场景 A：论文审查**：判断论文声称的贡献是否与前人研究存在实质性重叠、检查方法描述与前人工作的具体差异、发现指标定义/计算方式及比较条件中的潜在问题、关联已有审查知识。
- **场景 B：学术研究与学习**：从一篇论文逐步展开具体贡献、发现使用相同机制或解决类似问题的其他贡献、查看继承的前人工作与后续扩展、利用交互式图谱、双贡献对比和研究演化时间轴理解研究方向。

## 1.2 主要能力

1. 论文树（Paper → Contribution → Claim → Evidence / ReviewFinding）。
2. 自由拖拽、缩放、固定、展开、聚焦的全局学术知识星图。
3. 已审查与未审查论文的区分。
4. 贡献级语义检索。
5. 贡献冲突候选检测（`NOVELTY_OVERLAP`、`PARTIAL_OVERLAP`、`CONTRADICTORY_RESULT`、`METRIC_INCONSISTENCY` 及非冲突关系 `EXTENDS`、`COMPLEMENTARY`、`SIMILAR`、`UNRELATED`、`INSUFFICIENT_EVIDENCE`）。
6. 两项贡献的左右结构化对比（研究问题、核心机制、方法组件、前提假设、数据集、指标、主要创新声明、原文证据、关键异同与人工确认）。
7. 邻近贡献学习（同任务同机制、同任务不同机制、同机制不同任务）及从审查发现出发的反向探索。
8. 学术研究演化时间轴（Research Evolution Timeline）。
9. 历史审查经验关联。
10. 私有图谱（`PRIVATE`）与总体图谱（`GLOBAL`）范围切换。
11. 图谱生成开关（开关 A）及加入总体图谱共享开关（开关 B）。
12. 审查证据定位与人工确认（`CANDIDATE` → 确认 / 驳回 / 需更多证据）。
13. 图谱布局保存与恢复。

## 1.3 LLM 模块 Prompt 体系

- **P1：贡献与证据抽取**（抽取 `METHOD / METRIC / DATASET / THEORY / EMPIRICAL_FINDING / SYSTEM` 贡献、子论点与原文定位）
- **P2：贡献成对比较**（结构化对比两项贡献的研究问题、机制、组件、假设、数据集、指标、异同与候选判断）
- **P3：邻近贡献差异摘要**（客观总结核心机制、研究任务、假设和适用场景区别）
- **P4：证据核验**（检查引用证据存在性、原文位置对应性与可比性限制）
