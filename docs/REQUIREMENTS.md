# 论文复现预审：需求与界面范围

## 使用者与主要任务

- 研究者提供论文 PDF、论文链接与第三方代码，选择一张表或一项实验。
- 同一论文可有多个核查范围，范围与执行版本独立保存。
- 文献页码、原文、指标名称、报告值、容差与代码检查项需要可追溯绑定。
- PDF 解析只是定位候选文本；多列排版、表格和扫描件需要人工确认。
- 代码来自 GitHub URL 或 ZIP；文件清单只能证明材料线索，不能证明安装、训练或评测成功。
- 运行需要数据、权重、环境和执行入口；计算预算由人设置。
- 核查前允许保留草稿、补充材料、取消选择、编辑主张和重新确认。
- 材料变化或主张变更使旧的确认与本次运行绑定失效，历史报告仍保留。
- 材料准备、代码运行和指标对齐是不同结论，不能汇总成无依据的“论文可复现”。
- 反馈与运行记录沿用原有核查接口，人工纠正不覆盖原始证据。

## 本轮交付

真实 PDF 选取、浏览器解析与逐页阅读；GitHub 公共仓库文件清单读取或 ZIP 目录检查；浏览器持久化项目；可编辑、可确认的页码主张；运行条件与阻塞原因；本地 manifest 预检和现有执行器绑定；分层结果与项目导出。托管页保留样例报告入口，用户上传材料不套用样例结果。

浏览器链接登记不等于已读取论文；GitHub 文件清单不等于已 clone。任意仓库的依赖自动安装、自由命令执行、模型权重下载、自动生成可验证 probe 与整篇论文训练复跑，不由这次前端改版伪装实现。本地执行沿用明确的 task.json 适配与 Docker 隔离接口。


## 论文复现与系统自评分开（2026-10-29）

论文复现工作区回答第三方能否依靠公开材料重建实验。新增实验覆盖、复现条件两个阶段：

- 登记论文版本、核心结论、实验/图表、目标复现层级、验收协议与关联主张。
- 四层目标：运行成功、作者权重评估复现、重新训练复现、主要结论复现。目标选择与材料登记不生成层级达成证明。
- 八项条件：目标、代码版本、数据划分、环境、实验设置、执行流程、计算预算、结果验收。状态为未核查、已记录依据、存在阻塞或不适用；后面三种需说明依据或原因。
- 独立复现记录：审核人、干净环境、README 起点、额外指导、补丁及阻塞。区分材料、环境、预算、执行、统计、结果不一致和需要询问作者。
- 核心实验覆盖只统计关联到当前选中主张的登记实验，不能解释为这些实验已复现。

系统自评工作区评价 ArtiCheck 自身的判定与执行质量。教学样例从 4 份归档报告和固定注入映射计算 12 条逐例结果、宏 F1、召回率、误报率和弃权比例。1 个原始仓库的开发样例不代表真实论文效果；没有记录的完成率、人工介入、耗时和成本保留未测状态。

CORE-Bench 与 JudgeEval 入口展示任务类型与缺少的执行依据，不生成成绩或启动假评测。对照方案可记录模型/revision、数据版本、分组划分、对照系统、硬件、统一预算、冻结阈值及统计方法。方案与结果独立保存、导出。

本轮改动是前端需求与记录工作流；没有新增完整训练执行器、统计验收引擎或外部 benchmark 适配。论文检查记录随项目进入 IndexedDB 与项目 JSON，自评方案在独立 localStorage 键保存。教学项目的编辑只保留当前会话；用户项目持久化。两类数据不会互相生成指标或复现通过状态。


## 从声明转向材料与实测（2026-10-29）

八项条件增加实际清单、配置或日志上传，以及原文预览、文件指纹、字段有无检查；不以表单完成代替实验验收。服务器资源增加本地只读采集、目标服务器采集脚本与 JSON 上传，按带出处的实验下限比较 CPU、每卡空闲显存、可用 RAM 和所选磁盘空闲量。未获取、过期、未确认来源或不支持的指标保持未知。主机容量与当前短时 probe 的分配限制分别显示。

本轮新增确定性的资源采集组件，无需增加负责“猜测服务器”的 LLM 角色；其他条件采用材料与日志入口，语义核验、干净环境重建、完整实验调度和统计验收仍有缺口。状态和位置详见 [八项能力核对](IMPLEMENTATION_STATUS.md)。
