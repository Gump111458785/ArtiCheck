# 账户、协作进度与指标分组

在线入口：[ArtiCheck 工作台](https://articheck-workbench.edgeone.dev/#api-review)。

## 邀请制登录与账户管理

在线工作台采用**邀请制登录**。未登录访问工作台会先跳转至独立登录页 `/login.html`，登录成功后进入工作台。公开注册已关闭（`POST /v1/auth/register` 返回 `403 invitation_only`），账户由管理员在「个人中心 → 账户管理」或使用命令行工具 `scripts/manage_accounts.py` 统一创建、分发、停用、启用和重置密码。登录表单与个人中心密码输入框均采用眼睛 / 眼睛斜线图标切换密码可见性。

个人中心支持修改显示名称、修改密码和继续当前浏览器的项目。修改密码使其他登录会话失效。登录会话最长保留 30 天，密码采用独立随机盐与 PBKDF2-HMAC-SHA256（600,000 次）保存，浏览器通过 HttpOnly、Secure、SameSite=Strict Cookie 持有会话。登录及修改密码设有请求次数限制。

受邀账户会话直接作为上传、源码读取、模型审查、代码执行与报告查询的授权凭据，不再要求额外填写网站访问码。登录不放大全站模型或执行总额度。服务器为每个账户保存独立的随机报告身份，该身份不会返回前端。

原始材料和项目列表保存在当前浏览器，登录不会自动把其他浏览器的 PDF、代码或项目下载过来。界面按当前账户筛选本地项目，退出后切回游客项目；已有游客材料保留在游客视图中。服务器报告保留 7 天，账户资料另行持久保存，不包含原始 PDF 或 ZIP。

## 动态协作进度

提交后，工作台轮询实际服务端记录，依次展示材料解析、公开来源核对、联合审阅、适用时的交叉复核和报告整理。有执行计划时，继续显示实际排程、阶段执行、阶段核查与报告写入事件。每条活动记录包含时间、职责、状态与简短结果，失败和跳过单独记录。

文献审阅、代码检查和计划编排共享主审模型请求。交叉复核在适用条件和剩余时限内另行调用；实验执行与输出核查由运行时记录。六个角色表示职责分工，活动数量不等于独立模型调用数量。页面不通过定时切换文案制造完成进度。

## 图表指标分类

图表证据按「数据集 → 指标类别 → 图表与评测协议 → 模型及报告值」排列。类别覆盖预测质量、效率与资源、损失与生成质量、鲁棒性与泛化，无法明确归类的指标进入其他指标。

默认展开第一个数据集和各类别的第一组，其他分组可展开。支持搜索模型、数据集、图表或指标，并筛选作者方法、对照方法。数量由筛选后的实际行计算。不同模型变体、单模型与集成、不同协议、单位和原始数值分别保留；分组不合并实验结果，也不修正论文报告值。出处仍可展开并返回 PDF 原页。

## 计算资源与受阻操作

正式 CPU 执行使用独立 E2B 模板：2 vCPU、4096 MiB 内存。实例启动后读取实际容量，小于服务声明的内存时停止，不上传执行代码。执行最长 600 秒，模型与实例继续使用原有持久化额度。

需要 CUDA 的阶段由自有 GPU 服务器（`10.30.41.183`，NVIDIA GeForce RTX 4090，24 GB 显存）拉取执行：通过私有 Redis 队列派发任务，在无特权 `bwrap` 命名空间与禁网环境中只读挂载预装 PyTorch + CUDA 运行时运行阶段命令。侧边栏底部「云端资源」按钮可随时查看当前 CPU 与 GPU 容量状态。

资源不足时，「可提供所需资源」与「确认无法提供」位于同一决策区；「使用本地环境」和「查看云端资源配置」另占一行。新建审查采用带加号的实心按钮，点击后先为项目命名。

## 账户接口

账户接口使用同域 Cookie、`X-ArtiCheck-Client: review-api` 与来源校验，不接收模型供应商密钥。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v1/auth/register` | 已关闭公开注册，固定返回 `403 invitation_only` |
| POST | `/v1/auth/login` | `username`、`password`；验证受邀账户并签发新会话 |
| GET | `/v1/auth/me` | 当前用户的公开资料（含 `role`）或 `null` |
| POST | `/v1/auth/profile` | 修改显示名称 |
| POST | `/v1/auth/password` | `current_password`、`new_password`；修改密码并轮换会话 |
| POST | `/v1/auth/logout` | 撤销当前会话并清除 Cookie |
| GET | `/v1/auth/admin/users` | 管理员列出全部受邀账户 |
| POST | `/v1/auth/admin/users` | 管理员创建受邀账户（`username`、`password`、`name`、`role`） |
| POST | `/v1/auth/admin/users/<id>` | 管理员执行 `reset_password`、`disable` 或 `enable` |

公开用户资料仅包含 `id`、`name`、`username`、`created_at`。密码散列、随机报告身份、会话令牌和供应商凭据均不进入响应。账户记录与会话沿用既有 Redis 服务，不增加月费服务。

## 核心实现

| 模块 | 职责 |
|---|---|
| `articheck/hosted_auth.py` | 密码、Cookie 会话、限流、账户报告身份 |
| `articheck/hosted_api.py` | 账户与浏览器授权、实际审查活动、资源能力接口 |
| `articheck/hosted_sandbox.py` | 执行模板、实际容量验证、实例生命周期 |
| `web/dist/account.mjs` | 注册登录、头像菜单、个人中心 |
| `web/dist/review-activity.mjs` | 角色活动与阶段事件展示 |
| `web/dist/metric-catalog.mjs` | 指标类别、多级分组与筛选 |
