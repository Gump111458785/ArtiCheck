# 在线审查与 CPU 执行

在线流程使用模型 API 识别材料、审查论文与代码、生成执行计划；E2B 在隔离 CPU 实例中运行计划。后训练权重不参与此流程。

## 用户流程

1. 打开网站的「在线审查」，新建项目。上传 PDF、代码 ZIP，或填写公开 GitHub 仓库地址；允许只提供一种材料。
2. 默认自动识别需求，也可选择论文自查、复现评估或代码审查。指定范围和最长执行时间均为可选项；选择「只检查指定范围」后，该范围才变为必填。
3. 填入网站访问码并确认材料发送范围。访问码只保留在本页内存，不是供应商 API key。
4. 系统返回材料类型、八项条件、问题与建议、图表指标和覆盖缺口。作者自查检查文内可见数字与论证，不据此确认原始数据真实。
5. 有可执行计划且开启云端执行时，自动创建 CPU 实例。页面读取实际阶段状态、输出与退出码。实际受阻后才询问用户能否补料；确认不可得后记录受影响实验在当前条件下无法复现，不把跳过计为通过。
6. 在「执行与日志」「图表与证据」「角色记录」查看依据，导出 JSON 报告。浏览器关闭后任务仍受服务端最长时限约束。

原本地工作台与 v1 静态审阅 API 保留，分别从「本地项目」与「自托管 API」进入。

## 服务边界

| 项目 | 当前约束 |
|---|---|
| 请求体 | 5 MB，包含 JSON 与 base64；原始 PDF 与 ZIP 合计建议不超过约 3.5 MB |
| 代码来源 | 固定 GitHub 提交的源码 ZIP，或用户导入的 ZIP；目录指纹不能代替源码 |
| 模型上下文 | 有界论文与代码节选；论文按页优先提供图表片段，代码先提供说明、依赖和根目录源码 |
| 指标 | 图表编号、页码、逐字引用与数值须能对应；作者方法优先。模型不能读取的纯图像曲线保留覆盖缺口，不生成精确值 |
| 论文类型 | 实验研究、诊断/分析、综述、非论文、未知；不适用条件单独标记 |
| 执行 | CPU；选填 30–600 秒，默认 300 秒；实例另留最多 60 秒准备时间，到期销毁 |
| 进程限制 | 独立无 sudo 用户；最多 64 个进程、3 GiB 地址空间、单文件 128 MiB；数值库线程限制为 2 |
| 网络 | 允许 PyPI、GitHub、UCI、Hugging Face、PyTorch 等配置的公共依赖与数据源；其他来源受阻时保留具体失败记录 |
| 结果 | 退出成功、数值在容差内与论文结论成立分别记录；不自动宣称完整论文复现 |

图表识别、不同论文类型的审查质量和真实论文全流程验收须分别验证。功能回归、教学材料和 CPU 连接检查不能替代这些质量评测。

## 存储与费用

- PDF 与 ZIP 留在当前浏览器。提交时发送至服务端解析；有执行任务时将代码放入隔离实例，不向实例注入模型、Redis、EdgeOne 或 E2B 密钥。
- Redis 保存浏览器身份隔离的审查报告、计划、执行状态与费用预留，保留 7 天；不保存原始 PDF/ZIP。报告可能包含材料中的引用、源码路径和执行输出。
- 浏览器生成随机身份凭据。其他浏览器不能仅凭任务编号读取报告；清除浏览器存储后原身份不能自动恢复，应先导出报告。
- 模型调用沿用原费用计数，最多 60 次，每次保守预留 1 元；CPU 执行最多 20 次，每次预留 1 元。总预留 80 元，低于本轮 100 元授权；余额查询/日志/报告读取不新建实例。
- 预留在外部调用之前原子完成，失败不退回。供应商不可用时不自动重试；重复提交同一 `request_id` 不重复请求模型，重复执行同一冻结计划不重复创建实例。
- 云端不依赖后台线程或本地文件队列。长任务由 E2B 实例执行，浏览器轮询同域接口，报告取回并保存后关闭实例。

E2B 免费额度、平台免费配额与实际账单以各控制台为准。这里的「预留」是应用预算上限，不是已发生费用。

## 服务端配置

在 EdgeOne 现有环境变量之外添加：

| 变量 | 用途 |
|---|---|
| `E2B_API_KEY` | 创建和管理隔离 CPU 实例，仅服务端读取 |
| `ARTICHECK_MODEL_ATTEMPTS=60` | 模型预留次数，服务端只接受 1–60；不改变既有计数键 |

原有 `ARTICHECK_API_KEY`、网站访问码、Redis 凭据、预算 ID 与固定公开来源继续使用。凭据不能写入前端包、上传素材或版本库。

## 在线接口 v2

除能力查询外，请求携带 `Authorization: Bearer <网站访问码>`、`X-ArtiCheck-Client: review-api` 和 `X-ArtiCheck-Session: <浏览器生成的64位随机十六进制值>`。不接收客户端提供的供应商密钥或任意模型服务地址。

| 方法 | 路径 | 请求 / 返回 |
|---|---|---|
| GET | `/v1/capabilities` | 运行模式、配置状态、材料与执行限制 |
| POST | `/v1/repositories` | `{url}` → 固定提交、源码指纹、文件目录与有界源码 ZIP |
| POST | `/v1/assessments` | 可选 `paper` / `code`（至少一项），`task`、可选 `scope` / `max_seconds`、`request_id` → 审查报告或已存在任务 |
| GET | `/v1/assessments/{id}` | 身份隔离的报告与实际执行状态；不会重建实例 |
| POST | `/v1/assessments/{id}/execute` | `code` 与 `plan_sha256` → 同一冻结计划的执行状态；重验源码身份 |
| POST | `/v1/assessments/{id}/cancel` | 请求停止所选实例，保留已有证据；无法确认停止时不伪装为已停止 |
| POST | `/v1/assessments/{id}/feedback` | 受阻后提交 `answer: unavailable / can_provide`，记录材料可获得性，不改变科学验收为通过 |

`paper` / `code` 使用 `{name, content_base64}`。`request_id` 推荐使用无连字符 UUID；同一编号不得替换材料、任务目的、范围或时限。报告来源为 `model_api_review`，运行观测单独放在 `execution` 中。

错误返回稳定 `error.code` 与可操作信息。GitHub 受限、材料不完整、模型请求失败、实例启动失败、时间耗尽和结果不符不互相替代。

## 核心模块

- `articheck/hosted_review.py`：单材料入口、任务类型、模型审查和执行计划校验。
- `articheck/hosted_github.py`：固定主机的 GitHub 源码导入、提交冻结、大小与失败处理。
- `articheck/hosted_store.py`：持久化报告、浏览器身份隔离、原子预留与更新。
- `articheck/hosted_sandbox.py`：E2B 创建、代码上传、状态取回与销毁。
- `articheck/hosted_runner.py`：低权限命令执行、时间与资源限制、实际日志、指标观测和角色事件。
- `web/dist/online-workspace.mjs`：统一在线工作区；`online-core.mjs` 管理验证和身份；`online.css` 定义信息层级。

本地回归见 `tests/test_hosted_review.py` 和 `tests/frontend/online.test.mjs`。上线后的生产验收记录另行归档，不用本地回归冒充上线验收。
