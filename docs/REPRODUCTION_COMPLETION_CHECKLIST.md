# 八项缺口的完成验收清单

目标仍为补齐八项实际能力。下面的“剩余”没有因为自制样例或公开案例运行成功而自动消失。遇到材料不足时给出未知/阻塞是正确行为；不能把输入框、字段存在、单次命中或局部结果当作完整验证。

| 项目 | 已有权威证据 | 剩余实现与验收 |
|---|---|---|
| 1. 目标与整篇覆盖 | 全页图表引用候选、带页码引用、核心实验执行映射；LIBLINEAR 的未覆盖核心实验确实留在审计中 | 将候选与主要结论审核接入实验覆盖界面；完整范围的确认与结论验收形成同一条证据链，不能只选容易的实验就通过主要结论层级 |
| 2. 代码完整与版本一致 | 文件 SHA256 / Git blob SHA、Git HEAD、组件路径与 Python AST；内容变更测试能检出 | ZIP 实际内容指纹与安全导入桥接；未声明额外文件/修改的检查；核心方法的来源映射和显式语义审核，必要修补保留 before/after 指纹 |
| 3. 数据获取与可核对 | 实际哈希、ID 重复/交集、阶段输入输出；固定公开案例有下载校验脚本与真实运行证据 | 通用的受控数据获取、缺失/受限数据处理与预处理追踪；生成划分在训练前验证；浏览器材料与本地执行输入贯通 |
| 4. 环境重建 | Docker 无缓存禁网构建、immutable image ID、镜像内验证，已在真实 CI 执行 | 统一环境快照/期望版本比较、锁文件安装依据、框架/CUDA/驱动兼容核对；不支持或无设备时保留未知且能接收目标服务器证据 |
| 5. 实验设置 | 实际配置逐项比较、每个种子和方法的冻结配置、阶段后防修改 | 校验程序报告的实际使用配置；阶段类型、初始化、模型选择、停止和模型产物溯源，不能只检查 used-config 文件存在 |
| 6. 完整执行 | 实际准备/训练/预测/汇总矩阵；持久化 Docker 任务、取消、幂等和错误保留；网页已连接 | 浏览器导入材料到执行工作区的桥接；通过 HTTP 启动并成功结束的正向集成；阶段阻塞和原始证据的完整前端验收 |
| 7. 资源与费用 | 本机/上传硬件快照、真实子进程 RSS/CPU、墙钟、运行后磁盘占用，未知价格保留未知 | 实际执行环境身份与资源要求绑定；独立监测与 GPU profiling / 上传证据；明确采样峰值范围、磁盘变化、数据准备和构建等费用范围，不能只报固定预算 |
| 8. 科学验收 | 独立 accuracy/macro F1/MSE/MAE 重算、配对 bootstrap、缺失/失败不丢弃、基线/消融及参考值分开 | 公平控制项与调参预算核对；训练层级和主要结论层级从实际证据计算（当前仍保守为 false）；覆盖完整/不完整、波动内/外、失败、错误配置均有正反向验收 |

已完成的公开 CPU 验收是 LIBLINEAR Section 3.1 的声明范围：15 次运行、60 阶段。原作者划分、Figure 1 / rcv1 / 外部求解器仍未复现；它验证系统能执行并暴露范围缺口，不将这些缺口视为已完成。原始作业：[40857463535](https://github.com/Gump111458785/ArtiCheck/actions/runs/40857463535)。

代码、文档与私有预览同步也是交付的一部分。只有上表的剩余实现完成，并且各项检查在其实际适用范围内有直接证据，才结束本目标。模型后训练收益、正式外部 benchmark 和 50 仓库数据集不以本次 CPU 结果冒充完成。
