# 八项复现要求：实现位置与剩余缺口

核对日期：2026-10-29。这里按可执行行为列状态，不以表单数量判定功能完成。当前没有“整篇论文可复现”的自动验收器。

网页入口：论文复现 → 打开项目。项目阶段为「论文与代码 → 实验覆盖 → 复现条件 → 服务器核对 → 实验主张 → 运行条件 → 评估结果」。

|---|---|---|

## 代码位置

- [assessment.mjs](../web/dist/assessment.mjs)：实验覆盖、八项条件、独立复现记录及结果摘要的界面。
- [assessment-core.mjs](../web/dist/assessment-core.mjs)：八项定义、四层目标、覆盖计数、材料变更后状态失效及项目导出。
- [resource-workspace.mjs](../web/dist/resource-workspace.mjs)：服务器采集/上传/比对界面、八项材料上传、原文预览与 JSON 模板。
- [resource-core.mjs](../web/dist/resource-core.mjs)：服务器报告校验、容量比较、材料字段有无检查；不会把字段存在判为科学验证通过。
- [environment.py](../articheck/environment.py)：真实只读主机采集；浏览器可下载的 [collect-environment.py](../web/dist/collect-environment.py) 与该模块内容一致。
- [intake.mjs](../web/dist/intake.mjs)：PDF/代码导入、七阶段工作区、主张绑定与启动条件。
- [workbench.py](../articheck/workbench.py)：本地环境采集 API、现有预检与执行 API；[OpenAPI](../web/dist/openapi.json) 共 16 个 HTTP 操作。

## 证据含义

材料原文件保存在当前浏览器 IndexedDB，上传不会自动发送到私有预览服务器。项目 JSON 导出移除 Blob，保留文件指纹、字段检查、最多 8,000 字符的原文摘录和评审记录；完整原文件需单独保留。JSON 的 sha256 字段是用户声明的值，材料文件自己的 SHA256 是上传时实际计算的值，两者含义不同。

材料上传或移除会将该条件恢复为“未核查”；替换论文/代码也使既有条件和目标服务器确认失效。人工“已记录依据”与实际执行成功、统计验收分开。

资源报告要求来自本次实验的目标机器及存储位置，由用户确认。报告超过 15 分钟或时间异常时不据此给出满足判断；重新比较/进入页面会刷新判断，不代表持续监控。多卡显存不求和，按每卡空闲显存筛选。总内存不替代可用内存。上传报告不证明远端执行器已连接。即使硬件满足，当前 Docker probe 默认无 GPU、1 CPU、1 GiB 内存、最长 600 秒，不能由前端资源表解锁长时 GPU 训练。

### 当前继续处理的缺口

- 自动形成整篇实验/结论清单仍只发现图表引用候选，语义完整性需要带来源的人工核对。
- 通用数据获取与浏览器材料到执行工作区的导入桥接尚未完成；LIBLINEAR 有固定来源的下载校验脚本。
- 可重建环境已有真实 Docker 验证，但 GPU/框架兼容核对与不同锁文件的通用安装仍需补充。
- 训练阶段、模型与实际使用配置的验收规则、公平控制项及主要结论层级的自动聚合仍未完成，不能由运行成功代替。
- GPU 峰值、独立外部资源监测、峰值磁盘及完整费用仍需补充；RSS、墙钟与运行后占用已记录。
