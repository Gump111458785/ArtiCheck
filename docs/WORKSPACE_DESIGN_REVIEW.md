# 工作台界面设计与验收记录

沿用 taste skill 已确定的 framed-sheet 方向（seed 2011675619），保留 IBM Plex Sans、绿灰框架和白色工作区，无重抽。此次改动围绕以下实际对象组织：

- 当前浏览器项目、账户身份和游客项目分开筛选。
- 材料允许论文、源码或两者同时提供，单次代码包最大 100 MiB。
- 审查报告有八项条件、问题建议、图表指标和覆盖边界。
- 真实 ResNet 归档包含 105 项指标，分组总数必须仍为 105。
- 指标保留数据集、模型变体、图表、协议、数值、单位和原页出处。
- 主审、交叉复核与实际运行事件有不同来源，不能用角色数量冒充调用数量。
- CPU 实例实际为 2 vCPU、4096 MiB，GPU 本轮仅保留入口。
- 资源补充是一项判断，切换本地执行是另一项操作。
- 账户使用显示名称和首字头像，项目数字由当前浏览器的实际项目计算。
- 日常操作以桌面工作台为主，按用户要求检查 1440 / 1280 宽度。

主要问题与对应设计：

| 视图 | 首先回答的问题 | 处理 |
|---|---|---|
| 自动审查 | 当前在做什么，哪些职责参与？ | 六个职责状态行、实际活动摘要和可展开事件；不生成虚构思考流 |
| 图表证据 | 哪个数据集、哪类指标、采用什么协议？ | 数据集 / 类别 / 图表协议分层，作者优先，筛选与搜索 |
| 资源受阻 | 我能补资源，还是换执行位置？ | 两组操作分行，至少 12px 按钮间距和 16px 分组间距 |
| 登录 | 如何创建并使用自己的审查身份？ | 用户名密码表单，明确标签、错误反馈、显示密码和密码确认 |
| 个人中心 | 我的资料与最近审查是什么？ | 首字头像、真实项目计数、资料与安全表单、最近项目 |
| 工作区入口 | 如何开始新的审查？ | 38px 实心加号按钮，与项目选择器保持相同高度 |

实测结果见 [最终浏览器检查](evidence/final-ui-acceptance.json)。无 FAIL。保留的 warning：28px 标题符合 app-screen 的 18–32px 范围；12px 用于活动状态、来源和脚注，正文与行内操作使用 13–14px。源码阴影检查只命中实际浮动的账户菜单，符合该 skill 对菜单的允许条件。
